# ADO_REVIEW — независимое ревью (ADO-20)

Дата: 2026-11-14. Все замеры — на СИНТЕТИКЕ (`ado.synthetic`), данные организаторов не получены.
Окружение: 2 ядра, Python 3.13, PostgreSQL 16 (локальный), без Docker и npm.

## Что проверялось
1. Соответствие ответов `spec/api_spec.yaml` (контрактные тесты jsonschema по каждому ответу).
2. Жёсткие ограничения H1–H10: независимый валидатор на каждой версии полного дня.
3. События: заморозка, идемпотентность, 409/422, атомарность при исключении.
4. Хранилище: блокировки, дедупликация, отказ БД.
5. Производительность построения плана и ответа на событие.
6. Интерфейс: поведение во время долгого расчёта.

## Оставшиеся ограничения
1. **Docker не собирался** (нет демона и доступа к реестрам). Dockerfile и compose написаны, но
   первая сборка может потребовать правок.
2. **UI с настоящим Leaflet и `tsc`** не проверялся (нет npm); проверена сборка с заглушкой карты.
3. **SQLAlchemy/Alembic** не установлены: в тестах тот же DDL выполняется через pgwire-клиент;
   путь `SqlAlchemyDatabase` и `alembic upgrade` проверятся только в контейнере.
4. **Данные организаторов** не получены (присланные файлы — тоже синтетика `ado.synthetic`): качество на реальных данных не измерено, загрузчики
   проверены только на синтетике в формате спецификации.
5. Открытые вопросы Q1–Q3 (`ADO_DECISIONS.md`): совместные наряды не поддерживаются.
6. Один процесс и одна блокировка (D23): горизонтального масштабирования нет — для кейса достаточно.

## Готовность
Алгоритм, API, хранилище и интерфейс готовы и проверены на синтетике. Перед сдачей обязательно:
`docker compose up --build` на машине с Docker, открыть `/ui/`, прогнать данные организаторов
(`benchmarks/compare.py` после загрузки в `data/raw/`).
