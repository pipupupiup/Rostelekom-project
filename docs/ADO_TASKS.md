## Интерфейс диспетчера (ADO-18): что проверено (первая версия)

Сценарий Playwright + Chrome (сервер `uvicorn`, демо-день на синтетике, 70 событий):
пустое состояние → демо-день → карта, список нарядов, Гант (40 строк, ширина по окну) →
выбор сотрудника на Ганте (маршрут на карте, таблица остановок с объяснениями) → 70 событий
(версия v1 → v71, вспышка показателей при обновлении) → вкладки «Риски» (11 LATE_RISK с
предложенными слотами), «Нераспределённые» (причины, перенос), «ПГП» (2 группы) → выбор наряда
кликом по Ганту (карточка) → фильтр по статусу → остановка сервера (баннер ошибки, последняя
версия остаётся на экране). Ошибок в консоли браузера нет. Скриншоты — `docs/screenshots/`.

Исправлено по итогам визуальной проверки: Гант не растягивался по ширине; при 40 маршрутах
карта превращалась в «паутину» (по умолчанию теперь показывается маршрут выбранного сотрудника);
подпись «единственный допустимый исполнитель» вводила в заблуждение; «повышенный риск» загорался
на всех инсталляциях из-за 10-минутного окна (теперь — только при отклонении прогноза от плана).

## Формула приоритета (ADO-05)

`priority = 1.0·repeat + 2.0·(1/n_eligible) + 1.5·tightness + 1.0·urgency + 0.5·duration_share`,
все компоненты в [0, 1]; `tightness` — узость оставшегося окна начала (cap 2 ч), `urgency` —
близость `latest_start` (cap 12 ч), `duration_share` — норматив / 3 ч. Без допущенных — в конец.
Приоритет задаёт очередь и тай-брейк в regret, но не ценность наряда (ценность = вес 1/2).
