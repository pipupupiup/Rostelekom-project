# AGENTS.md — правила работы кодового агента в проекте ADO

Проект: ADO (Adaptive Dispatch Optimizer) — сервис распределения нарядов и маршрутизации
выездных бригад для кейса ПАО «Ростелеком».

## Источники истины (по убыванию приоритета)
1. `spec/api_spec.yaml` — публичный API, форматы, жёсткие ограничения H1–H10, правила оценки.
   Не выдумывать поля, коды, перечисления. При конфликте с другими документами прав он.
2. `docs/ADO_DECISIONS.md` — принятые решения и допущения (D*, A*), открытые вопросы (Q*).
3. `docs/ADO_SPEC.md` — предметная область и цели.
4. `docs/ADO_ARCHITECTURE.md`, `docs/ADO_CONTRACTS.md` — структура и интерфейсы.
5. `docs/ADO_TASKS.md` — статус модулей ADO-01…ADO-17. Обновлять после каждого модуля.

## Порядок работы над модулем
1. Прочитать этот файл, ADO_TASKS.md и код зависимостей.
2. Сформулировать краткий план изменений.
3. Реализовать только заданный модуль и минимально нужную интеграцию.
4. Добавить тесты: основная логика, границы, недопустимые входы, нарушения ограничений.
5. Запустить `python -m pytest` и `ruff check . && ruff format --check .`.
6. Обновить ADO_TASKS.md (и ADO_DECISIONS.md при новых допущениях).
7. Отчёт: что сделано, какие файлы, какие тесты реально запущены и их результат, риски.

## Жёсткие правила
- Время внутри оптимизатора — `int` секунд от местной полуночи дня (`ado.domain.timebase`).
  Системные часы для модельного времени не использовать; `now` передаётся явно.
  Реальное время расчёта — только через `ado.optimization.budget.TimeBudget`.
- Жёсткие ограничения маршрута проверяет только `RouteSimulator` (ADO-07). Не дублировать.
- Никаких запросов к сети/БД во внутренних циклах оптимизации.
- Не подгонять алгоритм под ID из обучающего набора. Случайность — только с фиксированным seed.
- Не создавать заглушки, выдаваемые за готовую функциональность; незавершённое помечать в ADO_TASKS.md.
- Не менять публичные контракты (`ado.domain.*`) без обновления зависимых модулей, тестов и ADO_CONTRACTS.md.
- Не менять тесты ради прохождения ошибочной реализации. Не заявлять о незапущенных тестах.
- Не выполнять git push и необратимые действия без явного разрешения.
